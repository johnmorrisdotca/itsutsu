# What else to split out as open-source packages

Survey of itsutsu (`its-board-focus` at 0.449.1, plus the unmerged card, dice, Hitotsu and offline branches) and UmaKuma (`main`), 2026-09-30. Survey only: no code changed.

Already being split: Korokoro (dice), Kyuubu (cube), Tenka, Kumimoji.

**How "site ties" was measured.** A script followed every import out of the candidate's folder and counted the modules it reaches outside that folder. It also counted anything it pulls from Prisma, `server-only`, Next or React. Line counts leave out tests. Most of the game and puzzle code turned out to be pure already. Its only outside imports are the shared `Random` type, the `puzzles.types` / `party.types` shapes and a name table, which a package would bring along with it.

## Don't split (yet)

- **The online-table sync layer** (`party/online`, several-devices play): 64 outside modules, Prisma, `server-only`, inbox, XP, ratings and history. It is the site's own server, not a library. Revisit only if a second app needs the same tables.
- **Ratings, ladders, XP, the bot ladder and bot budgets** (`rating/`, `xp/`, `bots/`): 26+ site imports each and tied to the database. `elo.ts` alone goes into Shoubu.
- **Word lists as package contents.** SCOWL (English, Gomoji and Kumimoji) is permissive and may travel with its notice. The German and French lists are **CC BY-SA 4.0** (Wiktionary / OpenSubtitles frequency), and the Japanese lists are **JMdict under the EDRDG licence** (share-alike). Putting either inside an MIT package puts share-alike terms on it. Ship game code with an "add your own list" hook, plus a separate data package under the matching licence if wanted. **The Pop list must never ship**: it is trademarked character and brand names (Pikachu, Mario, Netflix and so on).
- **Gomoji itself** (the five-letter word game): the code splits fine (~2,100 lines, internal imports only), but the Wordle look-alike invites a trademark complaint. If split, give it its own name and look, and no lists beyond SCOWL.
- **UmaKuma kanji data** (`src/data`, 80 MB): stroke order is KanjiVG (CC BY-SA 3.0), dictionary entries are KANJIDIC (EDRDG). A data package is possible under those licences with their attribution. `radicalNames.ts` reads **WaniKani's own radical names** from their API, and those are WaniKani's content: never publish them. The loaders use `node:fs` and `server-only`, so they would need rewriting anyway.
- **Anything React** (BoardFrame, PuzzleBoard, the pickers): every component reads site constants, picture sizes and routes. A UI package could come later on top of Narabe and Nazotoki, but not now.

## Suggested order

Tane, then Toranpu, then Hitoriasobi (these three lean on each other and are low effort). Then Kanamoji and Shoubu (small, quick). Then Narabe, then Yomi, then Nazotoki one puzzle at a time, then Asobiba. Kurikaeshi and Rusuban come last. Each follows the Korokoro layout: `packages/<name>`, tsconfig `paths`, vitest include, its own public repo under johnmorrisdotca.
